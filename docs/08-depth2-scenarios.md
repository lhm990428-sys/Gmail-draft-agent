# 뎁스 2 상세 화면 및 시나리오 검수

기준일: 2026-10-29 · 2단계 목업 보강 · 사용자 승인 대기

후속 재설계: [작업 흐름 중심 목업](09-workflow-redesign.md)에 따라 시나리오의 기본 링크는 통합 작업실로 연결됩니다. 기존 상세 URL은 ‘상세 원장으로 이동’ 보조 링크에서 접근합니다. 아래 상세 화면 설명과 이전 검증 기록은 심층 원장에 대한 기록입니다.

## 검수 시작점

로컬 주소: `http://127.0.0.1:5173/scenarios`

왼쪽 탐색의 **시나리오 검수**에서 시나리오를 선택하고 ‘이 시나리오 시작’을 누릅니다. 초기화 확인 뒤 각 단계의 ‘상세 화면으로 이동’을 따라가세요. 상세 화면 상단에서 시나리오 가이드로 돌아올 수 있습니다.

시나리오 선택만으로 데이터가 바뀌지 않습니다. 시작 확인 시 현재 탭의 합성 메일·실행·릴리스 변경을 초기화합니다. 페이지 새로고침 시에는 기본 합성 상태로 돌아갑니다. 검수 의견은 별도로 브라우저 localStorage에 보관합니다. 다른 브라우저/사용자에게 자동 공유되지 않습니다.

## 10개 검수 시나리오

| ID | 주요 흐름 | 사용자 의사결정 / 기대 결과 |
|---|---|---|
| reply-review | 원문 확인 → 수정 저장 → 승인 → 이력 | 미저장 수정은 승인 불가. 저장 후 revision 증가, 승인 후 편집·재승인 금지 |
| risk-review | 민감 메일 → 위험 근거 → agent 계약 | 계약·견적과 미처리 첨부파일 경고를 보고 승인·수정·거절 판단 |
| stale-review | 이전 초안 승인 → 새 메시지 도착 → 409 → 최신 조회 | 미팅 시간이 2시에서 3시로 변경. 이전 승인으로 저장하지 않으며 최신 원문·초안을 다시 검토 |
| draft-uncertain | 승인 → 응답 유실 → 편집/결정 차단 → 결과 대사 | 같은 intent의 합성 Draft 확인. 재저장하지 않고 `draft.reconciled`로 완료 |
| tool-timeout | 도구 3회 timeout → 실패 확인 → 수동 복구 재실행 | 기존 실패 이력 보존, 새 run ID 생성. 실제 probe가 아닌 복구 가정 |
| quality-regression | 실패 사례 → 진단 → 개선 실험 계획 → release | Quality 미달로 IMPROVE_REQUIRED. 후보 승격 차단 |
| missing-events | 이벤트 coverage 92% → 관측 신뢰도 경고 → release | UNKNOWN을 PASS로 치환하지 않고 HOLD. 승격 차단 |
| ready-release | manifest·8개 gate 확인 → 확인 모달 → 승격 결과 | READY_FOR_APPROVAL에서만 사람 승인 후 합성 Canary 상태 변경 |
| draft-saved | 저장 완료 메일 → 내용·revision·Draft ID·이력 | 결과 재확인 가능, 편집·재승인 불가 |
| review-rejected | 거절 완료 메일 → 거절 이벤트 | 외부 쓰기 없음, 검토 종료 상태 확인 |

## 피드백을 남기는 방법

시나리오 가이드의 ‘검수 의견’에서 다음 중 하나를 선택하고 메모를 저장할 수 있습니다.

- 현재 흐름 유지
- 수정 필요
- 추가 확인 후 판단

이 선택은 **제품 화면에 대한 검수 의견**이며 실제 릴리스 승인이나 Gmail 작업 승인이 아닙니다. 저장소에 비밀 키와 실제 메일 개인정보를 입력하지 마세요. 시나리오 데이터 초기화는 저장된 검수 의견을 삭제하지 않습니다.

## 구현 경계

- 기존 React / TypeScript / Router / TanStack Query / Zod / MSW 스택과 CSS 토큰을 유지합니다.
- 메일·실행·릴리스의 주요 인터랙션은 기존 컴포넌트를 focused 모드로 재사용합니다. 나머지 상세는 `details.tsx`, 검수 가이드는 `scenarios.tsx`에 구현합니다.
- 평가 사례와 manifest는 API adapter를 통해 조회합니다. UI가 mock fixture를 직접 읽지 않습니다.
- 시나리오 준비 API는 `/api/v1/mock/scenario`이며 mock 전용입니다. API 모드에서는 호출을 거부합니다. 실제 서비스에 이 엔드포인트를 구현할 필요는 없습니다.
- 재실행·대사·manifest·사례 API는 향후 백엔드 계약으로 문서화했습니다. 실제 동작·권한·영속성은 3~5단계에서 구현·검수합니다.
- 실제 Gmail, Hermes, LLM, LangSmith 호출, DB 저장, 배포는 하지 않았습니다. 모든 수치와 probe, 승인 기록은 합성입니다.

## 검증 기준

기존 8개 테스트와 뎁스 2/시나리오 테스트를 함께 수행합니다. 상세 URL 직접 접근·목록에서 진입·뒤로 가기·알 수 없는 ID, 정상 승인, stale 충돌, 불확실 저장 대사, 제한 재시도/새 실행, Quality/Hold 차단, 사람 승격, 검수 메모 보존, desktop/mobile의 가로 넘침과 렌더링을 확인합니다.

이 문서는 목업 검수 대상입니다. 사용자 승인 전에는 3단계 Tool 연동을 시작하지 않습니다.

### 최종 확인 기록 · 2026-10-29

- `npm run build`: TypeScript 및 production bundle 빌드 통과.
- `npm run test:e2e`: 기존 8개 + 상세/시나리오 11개 = **19개 전체 통과**.
- 이후 저장 불확실 이벤트의 run 상관 ID를 보강하고, 관련 기존 시험 1개 + 신규 회귀 시험 1개를 별도 출력 디렉터리에서 재검증하여 **2개 통과**. 최종 테스트 정의는 총 20개다.
- 기본 화면: 1440/1024/390/320px × 9개 = 36개 캡처. 상세/가이드: 1440/390/320px × 9개 = 27개 캡처. 페이지 가로 overflow 및 해당 탐색의 uncaught JavaScript 오류 없음.
- 상세 레이아웃이 목록용 그리드 폭을 상속하던 문제를 실렌더에서 발견·수정. 데스크톱 메일/실행 상세 작업 영역 폭이 900px 이상인지 회귀 조건 추가 후 통과.
- 동일 CSS 토큰과 주요 컴포넌트를 유지하고, 관찰 가능한 상태·실패·회복·의사결정 근거를 보강했다. UI 스킬의 실제 작업 중심 구성과 렌더/상태 검증 기준을 적용했다.
- 화면 캡처는 `frontend/test-results/depth2`, 전체 시험의 완료 표시는 `frontend/test-results/.last-run.json`, 추가 대사 시험은 `frontend/test-results-correlation/.last-run.json`에 있다. HTML report는 마지막 실행 결과로 덮어써지므로 현재는 추가 시험 2개를 표시한다.

확인하지 않은 것: 실제 OAuth·Gmail write·LLM 평가·LangSmith 전송·Gateway 연결·DB 내구성·운영 배포. 목업 시험 결과를 실제 시스템 검증으로 해석하지 않는다.
