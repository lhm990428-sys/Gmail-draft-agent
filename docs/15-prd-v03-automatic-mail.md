# PRD v0.3 — 자동 Gmail 처리 · 최소 비용 실습

**후속 사용자 지시:** 블랙톤·목업 단계와 누적 금액 예산 통제는 취소. 기존 화이트톤의 자동 Gmail 구현·검증을 승인했으며 [최신 실행 안내](18-automatic-gmail-review.md)를 따른다. 아래는 변경 전 설계 제안 기록이다.
상태: **설계 제안 · 사용자 승인 대기** / 2026-11-02. 이 문서는 구현 완료 보고가 아니다. 기존 v0.2 승인·구축 이력은 보존한다. 본 개정 승인 → 블랙톤 목업 검수 → 구현 → 기능 검수 → LLMOps 시연 순서를 따른다.

## 1. 달라지는 사용자 경험

사용자는 메일을 일일이 골라 에이전트를 실행하지 않는다. 최초 연결 시 최근 72시간의 받은편지함을 가져오고, 앱이 켜져 있는 동안 새 메일을 자동 감지한다. 명확한 광고는 로컬 규칙으로 제외하고 나머지는 AI가 회신 필요 여부를 분류한다. 회신이 필요하면 자동으로 초안을 준비한다. 사용자는 처리 과정과 결과를 확인하고 초안을 수정·검토한다.

이번 실습에서는 **앱 내부 초안까지만 저장**한다. Gmail Draft 저장과 발송은 비활성화한다. ‘검토 완료’는 앱 안의 결정이며 Gmail 저장 성공으로 표시하지 않는다. compose 권한 추가는 별도 범위다.

## 2. 범위와 기본값

| 항목 | v0.3 제안 |
|---|---|
| 최초 수집 | 연결 시점 기준 과거 72시간, 받은편지함 `INBOX`. 화면 시각은 KST |
| 포함 | 읽음/안읽음 모두. 자신이 자신에게 보낸 테스트 메일도 INBOX에 있으면 포함 |
| 제외 | 보관처리된 메일·휴지통·스팸·Draft·첨부 내용·외부 링크 방문 |
| 이후 감지 | 로컬 앱 실행 중 30초마다, 서버 측 단일 수집기. 브라우저 탭 수와 무관 |
| 작업 분모 | 새 수신 message ID. 스레드 전체를 매번 새 실행으로 처리하지 않음 |
| 수집 분량 | 한 페이지 20건, 한 동기화 주기 최대 100건. 초과분은 다음 주기 대기 |
| AI 처리 | 기본 직렬. 신규 메일 우선, 최초 이력은 순차 처리. 예산 부족분은 대기 표시 |
| 모델 | 기존 GPT-5.4 mini snapshot 유지. 모델을 바꿀 때 별도 품질·가격 계약 검증 |
| 실습 예산 | 이 앱의 새 실습 캠페인 누적 $1.00. 재시작·날짜 변경으로 초기화 금지 |
| 실행 제어 | 전체 자동 처리 일시정지/재개, 다음 확인 시각, 마지막 성공·오류 표시 |
| 반복 | 같은 message ID 재수집·새로고침·재시작 시 추가 AI 호출 없음 |
| 보관 | 민감 본문/초안 기본 7일 암호화. 원장·message ID hash·제외/오류 사유 유지 |

‘최근 3일’은 한국 날짜 3개가 아닌 **연결 시점에서 72시간**이다. API 검색에는 UTC epoch 경계를 쓰고 `internalDate`로 다시 검증한다. 처음 조회 시각을 고정하고 페이지별 동일 경계로 수집한다. 받은편지함 밖까지 확대하는 것은 이번 승인 범위에 포함하지 않는다.

## 3. 자동 업무 흐름

1. 서버가 OAuth readonly와 수집 범위·유료 모드 활성화 여부를 검사한다.
2. Gmail에서 해당 범위의 ID·라벨·필요 헤더를 읽는다. 단계별 최소 데이터를 조회하고 읽음 상태·라벨을 바꾸지 않는다.
3. 이미 처리 중이거나 완료한 message ID는 건너뛴다. 신규 ID의 작업과 수집 cursor를 같은 로컬 트랜잭션으로 기록한다.
4. 명확한 대량 광고·자동 알림을 로컬 규칙으로 제외한다. 제외는 삭제/보관처리가 아니며 사유와 규칙 버전을 목록에 남긴다.
5. 나머지는 Triage AI가 한 번에 `REPLY_REQUIRED / NO_REPLY / REVIEW_REQUIRED`와 근거 위치, 확신도, 위험 신호, 요청 요약을 반환한다.
6. 감독기는 결과를 검증한다. 회신 불필요면 끝내고, 모호하거나 위험하면 사람 검토로 보낸다. 회신 필요면 Draft로 위임한다.
7. Draft 작성 → 독립 Critic 검토 → 사람 검토. 실습에서는 자동 재작성 0회, 최대 3회 LLM 호출이다. Critic 불합격은 숨기지 않고 사람이 확인한다.
8. 모든 노드 전환·호출·예산·제외·오류·수정·검토 결과를 원장 및 LLMOps에 연결한다.

제목/발신자 한 가지 단서만으로 광고라고 확정하지 않는다. Gmail Promotions 라벨 + 대량 발송/수신 해지 헤더 등 보수적인 복합 규칙을 사용한다. `noreply` 주소만으로 회신 불필요를 확정하지 않는다. 제외된 메일은 펼쳐 볼 수 있으며 사용자가 ‘제외 해제’를 선택하면 같은 예산 검사를 거쳐 분류한다. 규칙의 오분류도 평가 대상으로 남긴다.

테스트 라벨은 **테스트 표식과 검색 편의용**일 뿐 자동 처리 대상의 필수 조건이 아니다. 사용자가 자기 Gmail로 테스트를 보내면 INBOX의 새 수신 메일로 자연스럽게 감지한다. Gmail 필터를 따로 만들 필요가 없다.

## 4. 감독과 확장

LangGraph Supervisor + Registry + 전문 subgraph 구성을 유지한다. 고정된 메일 업무의 분기·순서·예산·재시도는 결정론적인 Supervisor Controller가 관리한다. 이 컨트롤러는 LLM 감독 에이전트라고 표시하지 않는다. 새로운 업무/팀이 필요할 때 등록된 별도 Supervisor Agent를 사용할 수 있지만 실습 기본 경로에서는 호출하지 않는다.

Triage, Draft, Critic은 별도 prompt/schema/context를 가진 AI 에이전트다. Context 정규화와 Risk Policy는 코드 노드다. Triage의 문맥·위험 신호 추출은 같은 호출 안에 합치되 코드 안전 검사와 사람 검토를 유지한다. 기존 독립 Context/Risk LLM 호출을 생략하는 **실습용 비용 절약 profile**이며, 기존의 독립 위험 탐지와 같은 품질이라고 주장하지 않는다. 향후 고위험 profile에서는 기존 독립 에이전트들을 다시 활성화할 수 있다.

새 에이전트/하위 팀은 AgentSpec 계약, 허용 도구, schema, 버전, 예산, trace 계약을 통과해 등록한다. 사용자의 메일 내용으로 agent/tool을 자동 설치하지 않는다. 팀의 새 LLM 호출도 동일한 전역 예산을 예약해야 한다.

## 5. 새 답장·중복·복구

- 신규 수신 message마다 `accountRef + messageId`를 고유 키로 저장한다. Gmail 계정 주소는 클라우드 trace에 넣지 않는다.
- 스레드에 다른 새 수신이 오면 새 실행을 만든다. 이전 초안은 `SUPERSEDED`로 표시하고 기존 검토의 유효성을 취소한다. 이전 초안을 새 메일의 결과로 재사용하지 않는다.
- 사용자가 이미 답장한 스레드는 최신 송수신 순서를 확인하고 `ALREADY_REPLIED`로 처리한다. 이후 새 수신은 다시 판단한다. 자기 자신에게 보낸 INBOX 테스트는 단순 SENT 포함만으로 제외하지 않는다.
- 본문은 최신 수신 및 필요한 문맥에 한정한다. 72시간 밖의 과거 본문은 자동 반출하지 않는다. 문맥 누락·긴 본문·첨부만 있는 메일은 `REVIEW_REQUIRED`로 전환한다. 잘린 문맥을 완전한 입력으로 간주하지 않는다.
- 단순 폴링은 최근 72시간의 message ID를 중복 검사하며 페이지 작업을 이어간다. 변경 목록/`historyId`는 최적화에 사용할 수 있으나 만료 시 범위를 제한해 재동기화한다. cursor만 앞서 진행해 미처리 메일을 유실하지 않는다.
- 재시작 후 이미 접수된 작업은 기록으로 복구한다. 유료 요청이 전송됐으나 결과를 모르면 `UNKNOWN_CHARGE`로 정지하고 자동 재전송하지 않는다.
- 앱 중지/절전/인터넷 단절 중 자동 실행은 없다. 72시간 이상 꺼져 있었을 때 누락 기간을 표시하고 오래된 메일까지 임의 확장하지 않는다.

## 6. 최소 비용과 예산

계산 기준은 input $0.75 / output $4.50 per 1M tokens다. 분류 1회 입력 1,000/출력 100토큰이라는 **가정**에서는 $0.0012, 100건 약 $0.12다. 실제 한국어 본문·시스템 prompt·schema 길이에 따라 달라진다. 초안과 Critic·별도 평가/진단은 추가 비용이다. 환율 1,400원 가정 시 분류 100건은 약 168원이며 환율·세금은 청구와 다를 수 있다.

새 실습 캠페인 $1 중 자동 호출에 사용할 admission 한도는 $0.80, 나머지 $0.20은 보수적 여유다. 모든 AI 경로는 **하나의 영속 예산 원장**을 공유한다. Draft를 시작하기 전 Draft+Critic을 함께 예약하고 불확실한 과금은 전액 예약 상태로 유지한다. 호출 상한/예산 계산은 [아키텍처](16-architecture-v03.md)의 계약을 따른다.

이것은 이 앱의 허용된 모델 호출 통제다. 다른 앱·외부 API 키 사용·LangSmith 유료 플랜·세금·환율까지 포함해 OpenAI 계정의 전체 청구액이 $1 또는 $5 이하라고 보장하지 않는다. 구현 검증 전 ‘하드 상한 보장’으로 표시하지 않는다. 사용자가 처음 충전한 $5와 이 캠페인의 소비 한도 $1은 별개다. 새 캠페인 생성/한도 증액은 사람이 명시적으로 수행하고 이력을 남긴다.

## 7. LLMOps는 운영 판단 단위를 유지

| 기능 | 실습 기본 동작 |
|---|---|
| 이벤트 | 규칙·감독·AI·Gmail 읽기·수집·예산·재시작·오류·수동 검토까지 전부 로컬 원장 |
| LangSmith | root → controller/agent/tool → 실제 LLM leaf, metadata·usage·점수·hash만. 민감 원문은 암호화 로컬 상세 |
| Eval | 매 실행 schema/정책/중복 검증 점수. 사람의 회신 필요/불필요 정정으로 분류 점수. 개발용 합성 10건의 잠긴 세트는 예산 안에서 명시 실행 |
| Critic | 초안이 있는 업무에만 AI 1회. 이것을 독립 holdout 품질 측정으로 대체하지 않음 |
| Observe | role별 실제 provider 토큰·추정 USD·호출 지연·queue 대기·poll 상태·예산 예약/미정산·재처리 방지 건수 |
| Diagnose | 코드 건강 진단 자동. 원인 가설 AI는 버튼으로 요청 시만 호출하고 같은 예산에서 차감 |
| Release | DEBUG / IMPROVE / HOLD / READY 판단. 작은 실습 데이터로 운영 준비 완료 판정 금지 |

LangSmith 기존 US 계정·프로젝트 분리를 유지한다. 무료 포함량·현재 사용량을 연결 단계에서 확인하며 새 유료 플랜·결제·유료 retention을 활성화하지 않는다. 전송이 꺼졌거나 quota가 부족하면 `LOCAL_ONLY / DELIVERY_PENDING`을 표시하고 원장을 보존한다. 클라우드 대사 누락을 성공으로 표시하지 않으며 release는 HOLD다. 상세 원문 전체를 LangSmith에 자동 전송하지 않는 개인정보 계약도 유지한다.

## 8. 블랙톤 화면 계약과 뎁스 2

주 화면은 기존 세 가지를 유지한다. 신규 화면을 별도로 흩어 만들지 않는다.

| 화면 | 1차 작업 | 같은 맥락의 상세 |
|---|---|---|
| 메일 작업실 | 최근 72시간 목록, 자동 처리 상태, 회신 초안 검토 | 한 메일의 원문·분류 근거·노드 진행·초안·Critic·수정·검토 이력 |
| 실행 감독 | 실제 Supervisor/agent/tool 노드·엣지·실행 시점 | task/input/output/public memory/checkpoint와 예산 reservation |
| LLMOps 판단실 | Eval·Observe·Diagnose·release 판단 연결 | 실패 사례·오분류 수정·버전 비교·예산 원장·전송 대사 |

상단에 `최근 72시간 / 자동 처리 실행·일시정지 / 마지막 확인 / 다음 확인 / 사용·예약·잔액`을 항상 보여준다. 처음부터 ‘테스트 실행’을 눌러야만 시작하는 구조를 제거한다. 목록 클릭은 결과를 살펴보는 행위이며 AI 처리를 시작하는 필수 단계가 아니다.

제안 색 토큰: 배경 `#0B0F14`, 탐색/작업면 `#111827`, 선택/상세면 `#1B2533`, 본문 `#E5E7EB`, 보조 글자 `#A7B0BF`, 행동 `#8AB4FF`, 완료 `#6ED6A1`, 검토/예산 대기 `#F4C76B`, 오류 `#FF8A8A`, 경계 `#364152`. 완전 검정 위 과한 발광·gradient·장식 카드 지양. 색+문구+아이콘으로 상태 구분. 다음 목업에서 실제 text/control 대비·focus ring·차트·모달·toast·320/390/1440px를 검증한다. 현재는 색 방향 승인용이며 목업은 아직 제작하지 않았다.

필수 상태: 초기 수집/빈 목록/광고 제외/분류 대기/분류 중/초안 중/검토 필요/회신 불필요/문맥 부족/인증 만료/오프라인/동기화 지연/예산 대기/과금 미확정/새 답장으로 초안 만료. 재생 화면은 과거 상태임을 표시하고 그 상태의 초안으로 현재 결정을 내리지 못하게 한다.

## 9. 요구사항과 검수 증거

| ID | 수용 기준 |
|---|---|
| AUTO-01 | 최근 72시간 INBOX만 수집. 경계 전후·KST 표시·자기메일·pagination 테스트 |
