# v0.3 설계 검수 안내

**후속 사용자 지시:** 블랙톤·목업 단계와 누적 금액 예산 통제는 취소. 기존 화이트톤의 자동 Gmail 구현·검증을 승인했으며 [최신 실행 안내](18-automatic-gmail-review.md)를 따른다. 아래는 변경 전 설계 제안 기록이다.
상태: **사용자 승인 대기** / 2026-11-02. 구현·목업 완료가 아니다.

먼저 [시각 설계 요약](design-v03-review.html)을 열어 자동 처리 / 예산 통제 / LLMOps 세 다이어그램을 본다. HTML과 SVG는 로컬 정적 문서이며 Gmail/모델을 호출하지 않는다. 색 띠는 블랙톤 방향 확인용이다. 화면 목업은 설계 승인 후 별도 제작한다.

1. [PRD](15-prd-v03-automatic-mail.md): 자동 처리 범위와 사람이 하는 일을 확인한다.
2. [아키텍처](16-architecture-v03.md): 감독·전문 역할 구분, 새 메일·중복·복구와 예산 통제를 확인한다.
3. 아래 네 가지를 승인하거나 수정 의견을 남긴다.

| 승인 항목 | 제안 |
|---|---|
| 자동 처리 범위 | 최초 최근 72시간 받은편지함 + 이후 새 수신. 사람이 메일을 골라야 시작하는 구조 제거 |
| 비용/품질 절충 | 코드 감독 + AI 분류 1회, 회신 필요 시 Draft/Critic 각 1회. 모호·위험은 사람 검토 |
| 실습 권한/예산 | 앱 내부 초안만, Gmail 쓰기·발송 없음. 새 캠페인 누적 $1 / 자동 admission $0.80 + 여유 $0.20 |
| 화면 방향 | 메일 작업실·실행 감독·LLMOps 판단실과 뎁스 2를 블랙톤으로 일관되게 적용 |

## 기존 구축본과의 차이

현재 앱은 수동 합성 실행과 기존 profile이다. 자동 받은편지함 수집, $1 누적 금액 예약, 비용 절약 profile, 블랙톤 화면은 **이 문서에서 제안한 다음 구현**이다. 과거 백엔드/브라우저 통과 기록이 새 기능의 통과 증거는 아니다.

이번 작성에서는 application.toml·실행 중 서버·Gmail 자격증명·frontend 소스·기존 DB를 변경하지 않았다. 실메일 조회, 유료 모델 호출, 신규 LangSmith 업로드도 하지 않았다. 기존 설계·승인 이력을 지우지 않고 새 제안을 링크했다.

## 목업에서 반드시 확인할 시나리오

| 시나리오 | 사용자가 확인할 결과 |
|---|---|
| 첫 연결 | 최근 72시간 범위, 목록 수집·분류 대기·초안 대기를 한 목록에서 확인 |
| 내가 테스트 메일 전송 | 버튼 없이 새 메일 감지 → Triage → Draft → Critic → 사람 검토 |
| 광고/영수증 | 규칙 제외 또는 AI 회신 불필요, 제외 이유와 AI 호출 수 0/1 표시 |
| 애매한 개인 메일 | 사람 검토로 이동, 확신도와 근거 확인 |
| 새 답장 | 이전 초안 만료, 새 실행과 과거 실행 연결 |
| 예산 부족/과금 미확정 | 유료 호출 중단, 목록은 유지, 예약/정산/잔액·재개 조건 표시 |
| 인증 만료·오프라인·재시작 | 오류 및 마지막 확인 시각, 재연결/중복 방지, 잘못된 성공 표시 없음 |
| LLMOps | 사례/trace/토큰/비용/건강/판정이 같은 release에 연결, 실습 증거 부족은 HOLD |
