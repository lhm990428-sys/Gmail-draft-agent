# 실제 Gmail 자동 처리 — 실행·검수 안내

기준일: 2026-11-02. 사용자가 v0.3의 블랙톤·목업 단계를 취소하고 기존 화이트톤으로 자동 처리 구현 및 연결 검증을 승인했다. 이후 누적 $1 예산 통제도 제외하도록 지시했다. **이 문서가 해당 범위의 최신 기준**이며 docs/15~17의 블랙톤·$1/$0.80 계획은 미적용 과거 제안이다.

사용자 검수: 다른 메일 계정에서 보낸 테스트 메일을 자동 감지하고 초안을 만드는 동작을 직접 확인했으며 현재 실습 기능이 충분하다고 피드백했다. 이는 자동 메일 기능 검수 기록이며 운영 품질 인증이나 LLMOps 시연 전체 승인과는 구분한다.

## 지금 사용하는 방법

1. 프로젝트의 `Open-Console.cmd`를 실행하고 자동으로 열리는 인증된 탭을 사용한다. 주소는 `http://127.0.0.1:8000/`다. 이미 앱을 실행해 둔 상태에서는 중복 실행하지 않는다.
2. 메일 작업실 위의 **최근 72시간 · 실제 Gmail** 목록을 확인한다. 받은편지함(INBOX)의 읽음/안읽음 모두 대상이다. 다른 폴더·보관처리·스팸·휴지통은 수집하지 않는다.
3. 앱이 실행 중이면 30초 간격으로 새 메일을 읽는다. 메일을 선택하거나 ‘테스트 실행’을 누르지 않아도 처리된다. 최초 이력의 페이지 수와 처리 대기량에 따라 완료까지 시간이 더 걸린다. 이전 페이지 수집 중에도 최신 첫 페이지를 함께 확인한다.
4. 테스트하려면 자신의 Gmail로 제목 `에이전트 실습 · 회신 요청`, 본문 `테스트 메일입니다. 잘 받았는지 짧게 회신해 주세요.`를 보낸다. 별도 라벨·필터는 필요 없다. 테스트 메일을 보내는 것은 사용자가 수행한다.
5. 목록에서 분류 대기 → 에이전트 처리 중 → 회신 불필요 또는 검토 대기를 확인한다. **처리 과정 보기**를 누르면 같은 메일의 원문·분류·초안·Critic·이력을 볼 수 있다. 실행 감독에서도 해당 run을 선택해 노드·task·공개 memory·입출력을 확인한다.
6. 수정 저장 후 **검토 완료**를 누르면 앱 안에서만 완료된다. 현재 Gmail Draft 저장과 발송은 비활성화돼 있다. Critic 수정/이관, 위험·불확실 분류는 사람 확인이 필요하다.
7. 멈추려면 **자동 처리 일시정지**를 누른다. 수집·신규 실행이 멈추며 이미 보낸 모델 요청은 계속 완료될 수 있다. 일시정지는 재시작해도 유지된다. 다시 누르면 재개한다. 앱 자체 종료는 실행 창 `Ctrl+C`다.

## 동작과 비용

- 명확한 Promotions 라벨 + 대량발송/수신 해지 헤더 광고는 로컬 규칙으로 제외한다. AI 0회이며 제외 이유를 표시한다. Gmail 원본을 삭제하거나 라벨을 변경하지 않는다.
- 일반 메일 분류는 AI 1회, 회신 필요 경로는 Draft와 Critic을 각 1회 추가한다. 자동 재작성 없이 최대 3회다. Supervisor/Context/Risk는 이 profile에서 CODE이며 독립 AI인 것처럼 표시하지 않는다.
- 위험·불확실 분류는 AI 초안을 강제로 만들지 않는다. 긴 본문(UTF-8 12,000bytes 초과)·본문 없음은 분류 대신 수동 확인 상태다. HTML은 실행하지 않고 텍스트로 추출하며 첨부·링크를 열지 않는다.
- 같은 message ID는 수집·재시작에 걸쳐 한 번 접수한다. 새로운 수신이 있으면 별도 실행을 만들고 같은 스레드의 이전 검토를 만료시킨다. 이미 답장을 보낸 오래된 수신이나 더 최신 수신이 있는 건은 생략한다.
- **누적 금액 제한은 없다.** 기존 안전 제한인 일일 모델 호출 100회·자동 접수 100건·실행당 3회·호출별 출력 상한은 유지한다. 남은 호출이 초안 경로에 부족하면 큐에 두고 다음 UTC 날짜에 재개한다. 이는 $5 지출 보장이 아니다.
- 기존 API 잔액에서 사용량이 차감된다. 자기 메일함에 도착한 일반 개인 메일의 본문도 분류 대상이면 OpenAI로 전송한다. 현재는 최신 수신 본문을 사용하며 장기간 스레드 전체를 모델 문맥으로 전송하지 않는다.

## 이력·LLMOps와 제한

새 수집·제외·모델 호출·검토 이벤트는 로컬 암호화 기록/원장에 저장한다. **사용자 요청으로 LangSmith 신규 전송을 재개했다.** 프로젝트는 `hermes-mail-dev-runtime-v2`이며 전송 대기 기록과 새 이벤트를 metadata·usage·점수·hash만 전송하고 서버 조회까지 대사한다. 메일 본문·주소·초안·공개 memory 원문은 클라우드 전송 대상이 아니다. coverage는 실제 확인 수치만 표시하며, 전송 완료가 운영 품질 인증을 뜻하지 않아 release HOLD와 구분한다. 새 유료 LangSmith 플랜이나 보존 옵션을 활성화하지 않았다. LLMOps 시연은 별도 검수 단계다.

전송 재개 결과는 `.local/reports/langsmith-resumed.json`에 저장한다. 메일 자동 처리의 기존 일시정지 상태는 그대로 유지한다. 기록 업로드·대사는 AI 모델을 호출하지 않는다. 실제 API 비용은 메일 처리·별도 AI 평가/진단을 실행할 때 발생한다.

2026-11-02 재개 확인: 대기 이벤트 852개와 재개 감사 이벤트 1개를 전송·서버 조회 대사했다. 당시 실제 Gmail 실행 19건 모두 coverage 1.00, 기존 대기 0개. 실제 LLM leaf의 로컬/원격 토큰 719 일치, 입력 비어 있음·출력 usage metadata만 포함·응답 지연 조회를 확인했다. 모델 추가 호출은 없었다. 새 콘솔 요청이나 새 실행은 이후 새 대기 이벤트를 만들 수 있으며 백그라운드가 계속 처리한다. 이 확인으로 Eval 품질/운영 release gate가 자동 통과되는 것은 아니다.

본인의 LangSmith 프로젝트에서 root/agent/LLM 이벤트를 확인한다. 원문과 회신 초안은 로컬 콘솔에서 조회한다.

API 인증/권한/요금 오류가 확인되면 자동 처리를 일시정지하고 오류 유형을 표시한다. 이미 실패한 메일을 자동으로 유료 재호출하지 않는다. OAuth 만료는 재인증 후 재개가 필요할 수 있다. 서버 종료·절전·인터넷 단절 동안은 자동 실행되지 않는다. 72시간보다 오래 앱을 꺼 두면 그 이전의 누락 메일을 임의로 가져오지 않는다.

민감 본문/초안은 기존 7일 보존 정책을 적용하고 수집 목록의 발신자·제목도 7일 이후 정리한다. 제외된 메일의 본문은 앱에서 자동 조회하지 않으며 해당 내역은 Gmail에서 확인한다. 광고 규칙 오분류의 앱 내 제외 해제와 오래된 스레드의 추가 문맥 조회는 이번 간소화 범위에서 제공하지 않는다.
